## 부록 A. 요구사항 세부 규칙 (본문 2장)

#### 2.2.1 R4, R4-2 세부 규칙
| 항목 | 내용 |
|---|---|
| 요약 대상 선정 | 심각도가 높은 순으로 최대 50건 (환경 변수로 변경 가능). 캐시에 있는지와 상관없이 같은 기준으로 정하고, 대상 중 캐시에 없는 항목만 요청 |
| 심각도 정보가 없는 항목 | 알려진 심각도의 항목 다음, 맨 뒤로 처리하고 표에는 "알 수 없음"으로 표시(낮음과 구분). 같은 심각도 안에서는 취약점 ID 순으로 정렬해 요청마다 순서가 같도록 함 |
| 요청 단위 | 5건씩 묶어 요청, 묶음마다 성공과 실패를 따로 판정 |
| LLM에 전달하는 정보 | 패키지명, 버전, 취약점 ID만 전달. 업로드한 파일의 내용·이름과 프로젝트 이름은 보내지 않음. API 키는 이미지에 넣지 않고 환경 변수로 전달 |
| 한도 초과 항목 | 요약하지 않고 표에 명시. `vuln-report`에는 항상 전체 항목을 표시하고, 응답의 표는 상위 15행(R3-2) |
| 항목별 요약 상태 | 요약됨 / 요약됨(재사용) / 요약 실패 / 요약 제외(한도 초과) / 요약 안 함(API 키 없음) |
| 실패 판정 | 정상 완료 응답이 아니면 원인을 구분하지 않고 요약 실패. 토큰 부족 전용 처리는 하지 않음 (X5) |
| 집계 | 요약을 시도한 경우 마지막에 `요약 N건 성공, N건 실패, N건 제외`를 응답에 담고 `vuln-report-<시각>.txt`에도 기록. "성공"에는 재사용분이 포함. 그 다음 줄에 `요약 호출 N회, 재사용 N건`(응답은 `summary.calls`, `summary.reused`). 요약을 건너뛴 경우(키 없음, 취약점 없음)는 집계와 이 줄 대신 건너뜀 안내 |
| 선행 조건(리스크)의 확인 결과 | OSV 응답에는 GHSA 항목의 문자열 등급(`database_specific.severity`)과 CVSS 벡터(v3 또는 v4)가 있고 PYSEC 항목은 벡터뿐이다. 등급 변환 규칙은 2.2.2에 정했다 |
| 실제 호출 방식 | 공식 SDK 없이 직접 HTTP 호출(`urllib`). 모델 기본값 `gemini-3.5-flash`(환경 변수로 변경), JSON 모드와 `responseSchema`, 생각 수준 `low`. 정상 완료는 "HTTP 성공 + `finishReason`이 `STOP` + 모든 항목의 설명과 권장이 있음" |
| 실패 원인 기록 | 응답과 화면에는 넣지 않고 서버 로그에만 짧은 메시지로 남김(예: `요약 묶음 실패 (5건): HTTP 429`). 키, 주소, 응답 본문은 기록하지 않음 |
| 사용 한도 | 무료 키는 모델당 하루 20회 요청. 한도가 차면 429가 나서 해당 묶음이 "요약 실패"로 표시됨(표, 이전 실행 대비, 이력, 링크는 정상). 한도는 모델마다 따로이며, 시연은 `SUMMARY_MAX_ITEMS=5`(점검 1번에 호출 1회)를 권장 |
| 치명적 오류 때 중단 | 한 묶음이 HTTP 429(사용 한도 초과), 401, 403(인증·권한)으로 실패하면 남은 묶음은 같은 이유로 실패할 것이므로 요청하지 않는다. 남은 대상 항목은 "요약 실패"로 표시하고 실패 건수에 센다. 서버 로그에 중단 사실을 한 줄 남김(`요약 중단: 남은 N건은 요청하지 않음 (HTTP 429)`, 키·주소·응답 본문 없음). 응답에는 원인을 넣지 않음. 그 외 실패(500, 503, 시간 초과, 응답 잘림)는 해당 묶음만 실패로 표시하고 다음 묶음을 계속 시도 |
| 요약 저장(캐시) | `/data/_cache/summaries.json`에 키 (패키지명, 버전, 취약점 ID), 값은 요약문(설명과 권장을 합친 한 덩어리), 저장 시각, 프롬프트 형식 버전(`v1`). 임시 파일에 쓴 뒤 이름을 바꿔 저장. `_cache`는 프로젝트 이름 규칙(영문·숫자로 시작)에 맞지 않아 프로젝트 폴더와 겹치지 않고 프로젝트 이름으로 쓸 수도 없음(400). 새로 저장할 때 TTL이 지난 항목은 지움 |
| 캐시의 공유 | 요약문은 패키지명·버전·취약점 ID에만 의존하는 공개 정보라서 프로젝트 사이에 공유해도 됨. 같은 항목을 다른 프로젝트에서 올려도 재사용 |
| 재사용 기간 | 환경 변수 `SUMMARY_CACHE_TTL_DAYS`(기본 30). 저장 시각이 TTL보다 오래된 항목, 프롬프트 형식 버전이 다른 항목은 재사용하지 않음. 0이면 캐시를 읽지도 쓰지도 않음 |

#### 2.2.2 R3, R3-2 세부 규칙 (구현에서 확정)
| 항목 | 내용 |
|---|---|
| 조회 단위 | (이름, 버전, 생태계) 하나씩 OSV `/v1/query`를 호출. 응답의 `next_page_token`을 따라가며 같은 ID는 한 번만 담음 |
| 심각도 변환 | ① 출처가 준 문자열 등급(CRITICAL=심각, HIGH=높음, MODERATE 또는 MEDIUM=보통, LOW=낮음) ② 없으면 CVSS v3 벡터의 기본 점수(9.0 이상 심각, 7.0 이상 높음, 4.0 이상 보통, 그 미만 낮음, 벡터가 여럿이면 최고점) ③ 그 외(CVSS v4 벡터뿐 등)는 "알 수 없음" |
| 별칭 합치기 | 같은 취약점이 GHSA, PYSEC 등 여러 ID로 등록되어 있으면 ID나 별칭(`aliases`)이 겹치는 기록을 하나로 합침. 표시 ID는 CVE 별칭이 있으면 CVE, 없으면 GHSA 우선. 심각도는 합친 기록 중 가장 높은 것. 합치는 범위는 한 (패키지, 버전)의 조회 결과 안 |
| 조회 실패 | 하나라도 실패하면 요청 전체를 실패(502)로 처리하고 부분 결과로 보고서를 만들지 않음. 시간 초과, 연결 끊김, 응답이 중간에 잘린 경우도 실패 |
| 정렬과 표 | 심각도 순, 같은 심각도는 취약점 ID 순(패키지와 버전으로 한 번 더)으로 요청마다 같은 순서. 응답용 표는 상위 15행 |

#### 2.2.3 R2-3, R2-4 세부 규칙 (구현에서 확정)
| 항목 | 내용 |
|---|---|
| 같은 시각 충돌 | 목록 파일을 "이미 있으면 실패"로 저장해 동시 요청에서도 덮어쓰지 않고 409. 같은 스캔 ID의 보고서만 남아 있어도 409. 충돌하면 조회와 요약을 하지 않음. 하드링크를 지원하지 않는 파일 시스템에서는 존재 확인 후 이름 바꾸기로 대신함 |
| 직전 목록 | 같은 프로젝트에서 파일명의 시각이 이번 요청보다 이른 것 중 가장 늦은 `sbom-<시각>.txt` |
| 읽을 수 없는 경우 | 헤더(`# SBOM 목록`)가 없거나, 항목이 0건이거나, 줄이 `이름 버전 생태계` 형식이 아니면 읽을 수 없음. 비교만 건너뛰고(더 오래된 스캔으로 넘어가지 않음) 이후 단계는 계속함 |
| 비교 기준 | (패키지명, 생태계). 비교 키를 만들 때만 PyPI 이름을 PEP 503 규칙(소문자, `-` `_` `.`의 연속을 `-` 하나로)으로 정규화하고 npm, Go, Rust 이름은 정규화하지 않음. 같은 키가 여러 줄이면 버전 표기를 한 번씩만 모아 비교 |
| 표시할 이름 | 이름 표기만 다르고 버전이 같으면 변경 없음, 표기가 달라도 버전이 다르면 변경. 화면과 파일에는 새 요청의 원문 이름을 쓰고, 없어진 항목은 이전 파일의 이름을 씀. 목록 파일의 이름 표기와 OSV 조회는 원문 그대로 |
| 구역 형식 | `추가 N: a 1 PyPI, b 2 PyPI`, `삭제 N`, `변경 N: flask 3.0.0 -> 3.0.1 PyPI`, `변경 없음 N`. 첫 요청은 `비교 대상 없음`, 읽을 수 없으면 `비교 건너뜀(직전 파일을 읽을 수 없음)` |

#### 2.2.4 R1-4, R1-5 입력 해석 세부 규칙 (구현에서 확정)
| 항목 | 내용 |
|---|---|
| 파일 종류 판별 | 업로드한 파일 이름(경로 부분은 무시)이 `package-lock.json`, `package.json`, `go.mod`, `Cargo.lock`과 정확히 같을 때만 그 형식으로 해석(대소문자 구분). 그 외 이름은 `requirements.txt` 형식. 이름이 같은데 내용이 형식에 맞지 않으면 400 "형식을 해석할 수 없음" |
| requirements.txt의 extras | 이름 바로 뒤에 붙은 `[a,b]` 형태만 읽고 버림(목록 파일, 조회, CycloneDX에 기록하지 않음). 공백이 낀 형태(`name [extra] == 1.0`, `[ async ]`), 닫히지 않은 대괄호, 빈 대괄호는 해석할 수 없는 줄. 닫는 대괄호 뒤의 공백은 기존 규칙(연산자 앞 공백)과 같게 허용. 범위 표기는 기존 규칙대로 `(확정 버전 아님)` |
| package-lock.json | `lockfileVersion` 2, 3의 `packages`. 키가 `""`(루트), `link: true`, 버전이 없는 항목, `node_modules/` 아래가 아닌 항목은 건너뜀(루트는 프로젝트 자신이라 건너뛴 수에 세지 않고 나머지는 셈). 이름은 키에서 마지막 `node_modules/` 뒤(`@scope/name` 포함). 모든 항목이 확정 버전. `packages`가 없는 lockfileVersion 1은 400 "지원하지 않는 lockfile 버전" |
| package.json | `dependencies`와 `devDependencies`. 정확한 버전(`x.y.z`, 프리릴리스·빌드 접미사 허용)만 확정. 그 외(`^`, `~`, `>=`, `*`, `latest`, URL, `workspace:` 등)는 원문(공백은 제거)을 `(확정 버전 아님)`으로 기록하고 조회에서 제외. 두 구역에 같은 이름이 있으면 둘 다 기록 |
| go.mod | `require` 한 줄과 `require ( ... )` 블록. `// indirect` 같은 주석은 버림. `module`, `go`, `toolchain`, `godebug`, `replace`, `exclude`, `retract` 줄(블록 시작·끝과 블록 안의 줄 포함), 빈 줄, 주석은 패키지 목록이 아닌 정상 내용이라 건너뛴 줄 수에 세지 않음. 읽을 수 없는 줄(버전이 없는 `require` 항목, 알 수 없는 지시어)만 셈. 버전은 `v` 접두사까지 원문 그대로 목록 파일, CycloneDX, OSV에 사용(OSV는 `v` 유무가 결과에 영향이 없음을 확인, 4.5) |
| Cargo.lock | `[[package]]`의 `name`, `version`. crates.io 레지스트리에서 온 항목(`source`가 `registry+`나 `sparse+`로 시작하고 `crates.io`를 포함)만 읽음. `source`가 없는 항목(프로젝트 자신, 경로 의존성)과 git 등 다른 출처는 건너뛰고 건너뛴 수에 셈. TOML 구문 오류는 400 |
| 공통 | 생태계 값은 `PyPI`, `npm`, `Go`, `crates.io`이고 OSV 요청에 그대로 씀. (이름, 버전, 생태계)가 같은 항목은 한 번만 조회(잠금 파일에는 같은 패키지가 여러 위치에 있음). 응답의 `skipped_lines`는 건너뛴 줄 또는 항목의 수 |
| 조회 병렬화 | 항목이 수백 건이므로 스레드 풀(기본 8, `LOOKUP_WORKERS`)로 동시에 조회하되 결과는 요청 순서대로 모음. 하나라도 실패하면 시작하지 않은 조회를 취소하고 502(R3-3). 실제 잠금 파일(조회 443건) 점검 시간: 순서대로 217.8초, 8개 동시 27.3초(컨테이너 35.6초), 16개 동시 15.1초 |

#### 2.2.5 R2-5 CycloneDX 세부 규칙 (구현에서 확정)
| 항목 | 내용 |
|---|---|
| 위치와 이름 | `/data/<프로젝트>/sbom-<시각>.cdx.json`. 시각은 같은 요청의 `sbom-<시각>.txt`와 같음(같은 스캔 ID). 목록 파일의 형식, 직전 목록 탐색, 비교는 바뀌지 않음. 이력 목록은 `sbom-<시각>.txt`만 스캔으로 세므로 `.cdx.json`이 섞이지 않음 |
| 최상위 | `bomFormat: "CycloneDX"`, `specVersion: "1.5"`, `version: 1`, `serialNumber`(프로젝트와 스캔 ID로 만든 uuid5, 같은 요청이면 항상 같음), `metadata.timestamp`(KST +09:00 ISO 8601), `metadata.component`(type `application`, name은 프로젝트 이름), `metadata.tools`(이 서비스 이름 `sbom-web`) |
| 구성요소 | 항목마다 type `library`, `name`(원문), `purl`, `bom-ref`(purl과 같음, 같은 purl이 겹치면 `#2`처럼 번호를 붙여 유일하게), 확정 버전이면 `version` |
| purl | PyPI `pkg:pypi/<소문자 이름, -_.의 연속은 ->@<버전>`, npm `pkg:npm/lodash@4.17.21`(스코프는 `pkg:npm/%40scope/name@버전`), Go `pkg:golang/<모듈 경로>@<버전>`, Rust `pkg:cargo/<이름>@<버전>`. 버전의 특수문자는 퍼센트 인코딩(`+`는 `%2B`) |
| 확정 버전이 아닌 항목 | `version`과 purl의 `@버전`을 넣지 않고 `properties`에 `{"name": "sbom-web:version-spec", "value": "<원문 표기>"}` |
| 중복 | (이름, 버전, 생태계)가 같은 항목은 한 번만(목록 파일은 줄마다 기록하는 기존 규칙 유지) |

| 문제 | 재현 조건 | 영향 |
|---|---|---|
